# Чеклист промежуточного этапа (до отбора в топ-10)

Источник: `data/rshb-digital-wine-scanner.md`, разделы 4 и 6. Здесь только то, что показываем экспертам: видео, питч, живое демо и контрольный прогон на звонке.

Что сдаём на этом этапе:

- [ ] Ссылка на открытый репозиторий (проверить из инкогнито-окна без логина).
- [ ] Видео-демо до 7 минут.
- [ ] Результаты прогона на публичном датасете: F1 top-1 / top-5, доля совпадений, время ответа.
- [ ] Презентация (питч до 7 минут).
- [ ] Готовность к живому демо и контрольному прогону на приватном датасете во время онлайн-звонка.

## 1. Цифры для видео и слайдов

Цифры собираем один раз, на той версии, которую покажем, и дальше везде используем одни и те же.

- [ ] Зафиксировать коммит демо-версии (тег, например `demo-intermediate`); после него не менять код.
- [ ] Прогнать официальный скрипт кейсодержателя на публичном датасете и сохранить `predictions.jsonl` и отчёт в `reports/eval/`.
- [ ] Итоговая таблица: доля совпадений, F1@1, F1@5, медианный отрыв top-1 от top-2 (у верных и у ошибочных ответов), p50 / p95 / max задержки, доля ответов в SLA ≤ 3 с.
- [ ] Указать железо, на котором мерили (GPU или CPU, модель, RAM): эксперты замеряют скорость на нашей машине.
- [ ] Один слайд честных ограничений: где ошибаемся (near-duplicates по году или сезону, блики, вина вне каталога).

## 2. Подготовка стенда (и для видео, и для звонка)

- [ ] Стек поднимается одной командой по README; проверено на демо-ноутбуке с нуля.
- [ ] Модели прогреты: 2–3 холодных запроса до начала записи или звонка.
- [ ] Выбрана `RANKING_EVAL_POLICY` (`matched` или `top1`), значение записано.
- [ ] Отключены отладочные экраны, которые не нужны в демо (`NUXT_PUBLIC_CATALOG_ENABLED`, `RANKING_DEBUG`).
- [ ] Сомелье в `live`-режиме: ключ рабочий, лимит `NUXT_SOMMELIER_MAX_REQUESTS` не мешает прогону; запасной вариант — `mock`, если провайдер недоступен.
- [ ] Выключены уведомления, закрыты лишние вкладки, в кадре нет чужих данных и ключей (`.env`, терминал с токенами).
- [ ] Телефон и ноутбук в одной сети; если показываем съёмку с камеры телефона, туннель или адрес по LAN проверен заранее.
- [ ] Запасной вариант на случай сбоя сети или стека: заранее записанное видео и скриншоты ответов API.

## 3. Набор фото для демо

- [ ] 3–4 «полевых» фото: у полки, под углом, с бликом, в плохом свете.
- [ ] Одна пара near-duplicates (одна серия, разные год или категория), распознанная верно, — главный аргумент по достоверности.
- [ ] Одно вино вне каталога: честное «не найдено» и похожие вина или аналоги из других виноделен.
- [ ] Каждое фото прогнано заранее на зафиксированной версии: ответ стабильный, время в SLA.
- [ ] Хотя бы одно фото снять прямо в кадре камерой телефона: это доказывает, что демо не подстроено.

## 4. Видео-демо (до 7 минут, без монтажных склеек)

- [ ] Сценарий по минутам (см. раздел 5), текст или тезисы у говорящего.
- [ ] Запись одним дублем: запись экрана или живой прогон, без склеек и ускорений.
- [ ] Время ответа видно в кадре: таймер в UI, DevTools → Network или ответ API с замером.
- [ ] Показать JSON-ответ сервиса: `{"slug": ...}` для скрипта и полный ответ с уверенностью для top-1 / top-5.
- [ ] Показать мобильный интерфейс: DevTools в мобильном режиме или экран телефона. Интерфейс на этом этапе не обязателен, но даёт плюс.
- [ ] Показать переход из карточки в доп. функцию (сомелье или аналоги).
- [ ] Показать прогон скрипта оценки хотя бы на части публичного набора с итоговыми метриками.
- [ ] Проверить звук, разрешение (не ниже 1080p), читаемость шрифта в терминале (увеличить размер).
- [ ] Длительность ≤ 7:00; файл открывается по ссылке без запроса доступа.

## 5. Питч (до 7 минут), структура из ТЗ

| # | Блок | Время | Что показать |
|---|------|-------|--------------|
| 1 | Концепция | ~0:45 | Боль покупателя у полки, почему Vivino не знает российских вин, одна карточка вместо списка |
| 2 | Архитектура пайплайна | ~1:00 | Схема: нормализация фото → признаки (DINOv2 + SIFT, OCR) → поиск в pgvector → ранжирование с порогом отрыва → карточка в JSON |
| 3 | Живое демо | ~2:30 | Сценарий из раздела 3, скорость видна экспертам |
| 4 | Метрики | ~1:00 | F1 top-1 / top-5, доля совпадений, отрыв top-1 от top-2, p50 / p95 |
| 5 | Функция после поиска | ~1:00 | Сомелье или аналоги: чем помогает удержанию пользователя |
| 6 | Выводы | ~0:30 | Что готово, ограничения, план до финала и внедрения на «Своё Вино» |

- [ ] Слайды в стилистике «Своё Вино» (дизайн тоже оценивается).
- [ ] Метрики на слайдах совпадают с отчётом в репозитории.
- [ ] Слайд со ссылкой на репозиторий и QR-кодом.
- [ ] Репетиция с таймером минимум дважды; укладываемся в 6:30, чтобы был запас.
- [ ] Распределены роли: кто говорит, кто ведёт демо, кто следит за временем.

## 6. Онлайн-звонок с кейсодержателем

- [ ] Заранее уточнить: как передадут приватный датасет, где запускается скрипт, как считается `null`, есть ли лимит на ответ.
- [ ] Стенд поднят и прогрет за 15 минут до звонка; прогнан smoke-тест.
- [ ] Демонстрация экрана проверена (показывается нужное окно, текст читаем).
- [ ] Скрипт кейсодержателя запускается на нашем сервисе одной командой; порт и путь эндпоинта записаны.
- [ ] Показ F1 для top-1 и top-5 после прогона (`scripts/eval_ranking.py --predictions ...`).
- [ ] Один человек ведёт стенд, второй отвечает на вопросы.
- [ ] Заготовлены ответы на вероятные вопросы: near-duplicates, почему такой порог отрыва, CPU или GPU, как добавлять ~50 вин в день, что уходит во внешние API.
