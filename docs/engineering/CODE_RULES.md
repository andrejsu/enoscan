# Правила разработки Vinolog

Этот документ обязателен для изменений приложения. Цель — предсказуемый код с проверяемыми границами, а не единообразие ради стиля.

## Рабочий цикл

1. Найдите затрагиваемый пользовательский сценарий и его контракт.
2. При изменении данных сначала обновите `apps/web/shared/contracts`, затем server API, затем UI.
3. Реализуйте один сквозной срез без параллельной временной архитектуры.
4. Добавьте проверку наблюдаемого поведения или чистой функции.
5. Завершайте изменение только после `npm run check` либо явно перечислите непрошедшие проверки и причину.

## Направление зависимостей

```text
pages → components → composables → /api
                                  ↓
shared/contracts ← server/api → retrieval adapter
```

- `apps/web/shared/contracts` содержит только TypeScript-типы, схемы и чистые функции. Он не импортирует Nuxt, Vue или серверную инфраструктуру.
- Страницы собирают сценарий и маршрутизацию. Повторяемая разметка живёт в компонентах; сетевое и сохраняемое состояние — в composables.
- Компоненты получают данные через typed props и сообщают действия через typed emits. Они не вызывают backend, если это не изолированный feature-компонент с явно описанной границей.
- `server/api` валидирует недоверенный ввод, вызывает адаптер и формирует HTTP-ответ. Поиск, OCR, ранжирование и бизнес-правила подбора не реализуются в обработчике маршрута.
- Внешние сервисы доступны только через server-side adapters и `runtimeConfig`; приватные URL и секреты не попадают в `runtimeConfig.public`.

## Nuxt 4 и Vue

- Используйте структуру Nuxt 4: клиентский код в `apps/web/app`, серверные маршруты в `apps/web/server`.
- `.nuxt` и `.output` — сгенерированные артефакты. Проверяйте проект через `npm run typecheck`; не редактируйте и не передавайте их `.d.ts` напрямую в `vue-tsc`.
- Компоненты пишутся с `<script setup lang="ts">`; props, emits и slots типизируются.
- Для данных страницы используйте `useFetch`/`useAsyncData`, для действий пользователя — `$fetch` из composable. Один запрос не должен неявно выполняться и на SSR, и повторно после hydration.
- Browser API (`localStorage`, `URL`, camera) вызываются только на клиенте: `onMounted`, обработчик события или `import.meta.client`.
- Состояния запроса моделируются discriminated union, когда поля зависят от статуса. Невозможные комбинации не кодируются набором независимых boolean.
- Автоимпорты Nuxt допустимы в `app` и `server`; в `shared` используются явные импорты.

## TypeScript и данные

- `strict` — базовый режим. `any`, необоснованный `as`, non-null assertion и подавление ошибок требуют локального комментария с причиной.
- Входы HTTP, localStorage и внешних API считаются `unknown` до runtime-проверки.
- Общие API-типы импортируются из `#shared/contracts`; локальные view-model туда не добавляются.
- Не создавайте поля, которых нет в каталоге. Отсутствующее значение остаётся `null` и получает честное отображение.
- `score`, `margin`, `probability` и конкурсные метрики — разные сущности и разные имена. Не преобразуйте similarity в проценты интерфейса.

## Контракты поиска

- Продуктовый ответ сохраняет три состояния: `matched`, `uncertain`, `not_found`.
- Оценочный ответ остаётся отдельным адаптером с единственным `slug`; его точный маршрут и имя multipart-поля берутся из официального скрипта.
- Ошибочный файл даёт 4xx с полезным сообщением. Недоступный retrieval или timeout даёт инфраструктурную ошибку, а не «вино не найдено».
- Top-1 продуктового и оценочного маршрутов формируется одним SearchService и одной версией индекса.

## Интерфейс

- Основная ширина проверки — 360–430 px; desktop расширяет композицию, но не меняет порядок сценария.
- Используйте токены из `app/assets/css/main.css`. Новые цвета и размеры сначала получают семантическую переменную.
- Интерактивный элемент имеет доступное имя, видимый `:focus-visible` и область касания не меньше 44 px.
- Все изображения получают осмысленный `alt` либо пустой `alt` для чисто декоративных.
- Анимация учитывает `prefers-reduced-motion`; загрузка блокирует повторную отправку.
- Текст сообщает следующее действие: переснять этикетку, убрать блик, выбрать другой файл. Аналоги визуально отделяются от совпадения.

## Имена и размер модулей

- Компоненты: `PascalCase.vue`; composables: `useThing.ts`; server routes: Nuxt-суффикс метода (`.get.ts`, `.post.ts`).
- Boolean начинается с `is`, `has`, `can` или `should`. Обработчик действия — `handleX`; emit — событие в прошедшем времени или команда пользователя.
- Если файл смешивает представление, запросы и правила предметной области, разделите по этим трём ответственностям. Число строк само по себе не является причиной абстракции.

## Проверки готовности

- Новая ветка состояния имеет UI и тестируемый способ воспроизведения.
- Изменение API покрывает успешный и ошибочный вход.
- Нет горизонтального скролла на 360 px, управление доступно с клавиатуры, reduced motion не ломает состояние.
- README и ARCHITECTURE обновлены, если изменились команды, границы или контракт.
